# consema-hcl fuzz targets (0.13.0 gate plan M2)

Per-format fuzz target set for the 0.13.0 quality gate (`docs/0.13.0-gate-plan.md` M2,
路线图 §15.3): parser, decoder, query, projection, materialization and edit entry
points with resource limits pinned to the production profile defaults.

## Harness equivalence

The target **logic** is in `fuzz_logic/` and is the single source of truth:

* **In-process deterministic harness (this machine, CI):** the files under
  `fuzz_logic/` are `include!`d by `crates/consema-conformance/tests/parse_fuzz.rs`
  and `tests/operation_fuzz.rs`, which run the same assertions under `cargo test`
  with a seed-based bounded mutational engine (`consema_conformance::fuzz`:
  flip/truncate/insert/delete/repeat/splice over committed seeds). This is the
  equivalent harness the gate plan allows ("cargo-fuzz 或等价 harness"): this
  Windows/MSVC machine has no clang, so `libfuzzer-sys` cannot link its C++
  runtime and `cargo fuzz run` is not available here.
* **libFuzzer (72 CPU-hours milestone M8, on a Linux host with clang):**
  `fuzz_targets/` are thin `#![no_main]` wrappers; run

  ```sh
  cargo +nightly fuzz run parse
  cargo +nightly fuzz run operations
  ```

  from this directory. Corpus seeds are committed under `corpus/<target>/`
  and the `fuzz/Cargo.lock` generated by the first build should be committed
  with the corpus (M8 evidence rule: unseeded runs are not evidence).

## Targets

* `parse` — `fuzz_logic/parse.rs`: parse closure over every production profile
  with `*ParseLimits::default()`; formed documents must render byte-exactly,
  cover the source exhaustively, keep kinds parallel to pieces, stay inside the
  diagnostic budget, and publish diagnostics when recovered. A resource-limit
  failure is a fatal formation error and therefore a pass, never a crash.
* `operations` — `fuzz_logic/operations.rs`: formation → operation gate.
  Query runs over formed documents (recovered included, the inspect path);
  recovered documents must be rejected by projection, materialization and edit;
  complete documents run projection → materialization → edit with the
  production default limits.

## Finding workflow

A violated invariant panics with the exact input (`FuzzFinding::render`).
The minimal input is committed to `conformance/corpora/mutation-v1.json`
(regressions section) per `conformance/corpora/README.md` before the run is
retried.
