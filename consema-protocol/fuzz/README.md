# consema-protocol fuzz targets (0.13.0 gate plan M2)

Protocol/PVCE/PGCE decoder fuzz target set for the 0.13.0 quality gate
(`docs/0.13.0-gate-plan.md` M2, 路线图 §15.3): the high-risk
protocol/varint/offset decoder entry points with resource limits pinned to the
production profile defaults.

## Harness equivalence

The target **logic** is in `fuzz_logic/decode.rs` and is the single source of
truth:

* **In-process deterministic harness (this machine, CI):** `fuzz_logic/decode.rs`
  is `include!`d by `crates/consema-conformance/tests/protocol_fuzz.rs`, which
  runs the same assertions under `cargo test` with a seed-based bounded
  mutational engine (`consema_conformance::fuzz`). This is the equivalent
  harness the gate plan allows ("cargo-fuzz 或等价 harness"): this
  Windows/MSVC machine has no clang, so `libfuzzer-sys` cannot link its C++
  runtime and `cargo fuzz run` is not available here.
* **libFuzzer (72 CPU-hours milestone M8, on a Linux host with clang):**
  `fuzz_targets/decode.rs` is a thin `#![no_main]` wrapper; run

  ```sh
  cargo +nightly fuzz run decode
  ```

  from this directory. Corpus seeds are committed under `corpus/decode/` and
  the `fuzz/Cargo.lock` generated by the first build should be committed with
  the corpus (M8 evidence rule: unseeded runs are not evidence).

## Targets

* `decode` — `fuzz_logic/decode.rs`: canonical `core.portable-value-json@1`
  decoding (`decode_json`), PVCE/1 varint decoding (`consema_pvce::decode`,
  `decode_value`, `decode_pvce`), and PGCE graph decoding
  (`consema_graph::decode_pgce`), all under the production default limits. A
  decode error is a pass; a successful decode must re-encode and round-trip
  exactly (canonical fixed point). The plist binary offset decoder is covered
  by the consema-plist targets.

## Finding workflow

A violated invariant panics with the exact input (`FuzzFinding::render`).
The minimal input is committed to `conformance/corpora/mutation-v1.json`
(regressions section) per `conformance/corpora/README.md` before the run is
retried.
